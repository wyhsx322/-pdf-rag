# ARCH-0001｜全仓分层架构与单向依赖边界基线

## 需求

- 将系统按职责拆分，保持单向依赖、高内聚和低耦合。
- 生产代码不得依赖评测代码，不通过兼容文件保留旧路径。
- 后续架构调整必须同步更新本分类文档。

## 功能

- 规定后端、前端、评测和运行时数据的边界。
- 规定跨模块调用方向，防止底层模块反向依赖页面或接口层。

## 实现逻辑

- 后端依赖方向为 `main → api → writing/memory/rag → core`。
- 前端依赖方向为 `app → pages → features → entities → shared`。
- RAG 再拆分为文档处理、切分、检索、生成和提示词五个子域。
- `evaluations` 可以调用生产模块，生产模块禁止导入 `evaluations`。

## 代码范围

- `server/`
- `frontend/src/`
- `evaluations/`
- 根目录启动、依赖和配置文件

## 依赖边界

- `core` 与 `shared` 分别是后端和前端的最低层。
- API 路由与页面只负责编排，不承载可复用底层实现。
