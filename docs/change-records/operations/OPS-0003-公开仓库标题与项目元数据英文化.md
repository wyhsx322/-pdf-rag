# OPS-0003｜公开仓库标题与项目元数据英文化

## 修改背景

- 项目准备提交到 GitHub，需要提升公开仓库标题、README 和包元数据的可搜索性与可信度。

## 原始需求

- 用户希望将“更好的辅助论文写作”命名为英文标题，并避免提交不该提交的本地内容。

## 历史与重复检查

- 已检查 `OPS-0001`，其中定义了依赖安装、服务启动、本地配置与数据边界。
- 当前没有已有变更记录覆盖公开仓库标题和 Python 项目元数据英文化。

## 问题原因

- README 一级标题仍是中文标题，不能充分覆盖英文搜索关键词。
- `pyproject.toml` 使用旧项目名 `lc-course` 和占位描述 `Add your description here`，不适合作为公开仓库元数据。
- `uv.lock` 中的虚拟项目包名需要与 `pyproject.toml` 保持一致。

## 影响范围

- 影响 GitHub README 展示、Python 项目元数据和锁文件中的本地项目包名。
- 不影响依赖版本、运行时配置、API、数据库或业务逻辑。

## 实现逻辑

- README 一级标题更新为 `AI Research Paper Writing Assistant with PDF RAG`。
- `pyproject.toml` 项目名更新为 `ai-research-paper-writing-assistant`。
- `pyproject.toml` 描述更新为本地 AI 论文写作、PDF RAG、证据检索与引用感知初稿生成。
- `uv.lock` 同步虚拟项目包名。

## 变更文件

- `README.md`
- `pyproject.toml`
- `uv.lock`

## 验证方式

- 检查 Git diff，确认元数据改动范围明确。
- 检查 Git 状态和忽略规则，确认 `.env`、本地 PDF、数据库、日志、虚拟环境和构建产物不会被提交。

## 验证结果

- `git status --short --ignored` 确认 `.env`、本地数据、日志、虚拟环境、构建产物和内部 README 均处于 ignored 状态。
- `compileall` 后端与评估目录通过，未留下 `__pycache__`。
